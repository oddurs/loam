# Design

The book is set in the manner of Edward Tufte's: a wide outer margin carrying
notes and diagrams, figures placed beside the sentence that discusses them, and
a diagram grammar that spends ink on data and nothing else.

## Page

| | |
|---|---|
| Trim | 203 × 254 mm (8 × 10 in) |
| Margins | inside 22 mm, outside 68 mm, top 24 mm, bottom 28 mm |
| Measure | 113 mm |
| Margin column | 56 mm, with a 6 mm gutter |
| Figure widths | `column` 113 mm · `wide` 175 mm · `margin` 56 mm · `full` 181 mm |

The outer margin is the point. A 38 mm column — the first draft — is wide enough
for a note and nothing else; at 56 mm a real diagram fits, which is what makes
the Tufte layout more than a decoration.

`wide` is exactly `column + gutter + margin`, so a wide figure bleeds precisely
to the outer edge of the note column. A test asserts that relationship rather
than the millimetres, so there is one place to change it.

## Type

| | |
|---|---|
| Body | **ET Book** 11.5 pt — Edward Tufte's own digitisation of Bembo, vendored in `fonts/`, MIT licensed |
| Math | New Computer Modern Math |
| Code | JetBrains Mono |

ET Book's old-style figures matter more here than in most books: this one is
full of numbers in running prose, and lining figures would make every `0.2126`
and `6504 K` shout.

**Its cost, stated plainly.** ET Book maps 229 codepoints. It has no Greek, no
combining macron and no math relations — for a book whose every other sentence
contains a λ, that is a real constraint. Two answers, used together:

1. Variables belong in math mode anyway: `$lambda$` is correct typography *and*
   a glyph New Computer Modern certainly has.
2. `engine/draw/fonts.ts` parses ET Book's `cmap` and picks the family per
   string, because the SVG renderer resolves one family per text element rather
   than per glyph. `check` fails on any label the body face cannot draw.

## Diagram grammar

Every figure is authored at its exact printed size in points, so type inside a
diagram is set at the same optical size as the type beside it. `check` enforces
it: a mismatch means Typst would rescale the SVG and the labels would silently
fall below body size.

Rules, in order of how often they matter:

- **Range frames, not boxes.** Each axis line spans only where the data is, so
  the rule itself reports the extent. `Plot` does this by default; pass
  `span: false` for a full-width rule.
- **Direct labels, not legends.** A legend asks the reader to hold a colour in
  memory, look away, find it in a key, and look back. `plot.seriesLabel()` puts
  the name at the curve, in the curve's colour. Keep a legend only where it
  carries something a label cannot — the black-body figure's legend has a
  chromaticity swatch per temperature, and earns its place.
- **No gridlines by default.** `grid: "none"` is the default and should usually
  stay that way.
- **Marginal rugs where distribution matters.** `rug: [...]` on an axis draws
  Tufte's dot-dash marks for free on a line that would otherwise be empty.
- **Neutral furniture.** Axes, rules and labels are grey. In a book about
  colour, the only colour on a page is the colour under discussion.
- **Small multiples over one busy figure** wherever the comparison allows.

## The series palette

The book's own categorical palette is generated by the book's own algorithm
(`categoricalPalette`), under a worst-case constraint across normal vision,
deuteranopia and protanopia: ΔE_ok ≥ 0.158 under both deficiencies, 0.208 in
normal vision. If the method in Chapter 14 is wrong, the reader will see it in
every multi-series figure.

## Where we depart from Tufte

- **Figures are numbered.** Tufte mostly does not, because his figures sit where
  they are discussed. A technical book needs cross-references, so ours are
  numbered per chapter (`Figure 5.2`) and the number is set quietly.
- **Captions are fuller.** Tufte's captions are often a phrase. Ours argue,
  because in this subject the figure usually *is* the argument.
