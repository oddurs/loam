## Question

Some Markdown files in a docs folder are written by a program, not a person:
measure-of-the-world's `status.md` ("Generated by `make status`. Do not edit by
hand."), code-as-color's `outline.md` (generated from `outline/*.ts`). Others
are inputs to another program: code-as-color's `roadmap-intro.md` is the header
`cairn render` puts on `ROADMAP.md`, and its links are written for where they
end up, so every one of them is broken where it sits. How should loam treat
them?

## Why it has to be answered first

Before the index is generated (0030) and before `check` reports broken links
(0031): today the format reads all three as ordinary pages, so
`roadmap-intro.md` reports two broken links and no title on its first
adoption. And before staleness (v0.2): a generated page is kept true by its
generator, never by review, and flagging it stale would be noise.

## Options

1. **Say nothing; the project moves them.** `roadmap-intro.md` belongs beside
   `cairn.toml`, and `_`-prefixed names are already not pages (spec §7.2).
2. **An exclude list in `loam.toml`**, globs of files that are not pages.
   Changes which files are pages, so it costs a format number (spec §9): a
   format-1 reader would ignore the key and read them anyway.
3. **A frontmatter key**, `generated: make status`, that keeps the page in the
   index and out of the staleness check. Costs nothing in the format: a new
   optional key (spec §9).
4. **Recognise the "generated by" line** the way people already write it. A
   convention to guess at, which the format has so far refused to do.

## What would settle it

Adopting the three folders (0036). Count the files that are generated or are
another tool's input, and see whether moving them (option 1) is a thing their
owner would accept.

## Answer

**Two different things, answered differently.**

*Another tool's input is moved out of the docs folder.* code-as-color's
`roadmap-intro.md` moved to `cairn/roadmap-intro.md`, beside the backlog whose
roadmap it heads, with `render.header` pointing there (option 1). Its owner's
commit on the adoption branch is the evidence that the move is acceptable:
one line of cairn.toml and a rename. loam needed nothing.

*A generated page stays a page.* The adoption found two: code-as-color's
`outline.md` and measure-of-the-world's `status.md`. Both are read, and both
belong in the index, where they appear today with their "generated by" line as
the summary. Frontmatter added by hand would be gone after the next build, so
it was not added. For v0.1 that is the whole answer: nothing is broken, and the
index is honest about what the pages are.

What is still owed is for v0.2, where it matters: a generated page must never
be called stale, since its generator, not a review, keeps it true. That is
option 3, a `generated` key a generator can write, filed as 0068. Option 2, an
exclude list, would change which files are pages and so cost a format number,
for a problem moving one file solved. Option 4, recognising the sentence, stays
refused.
